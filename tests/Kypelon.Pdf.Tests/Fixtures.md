# Hardening fixtures

The in-memory FontFixture and FontHardeningTests builders are original Kypelon.Pdf test code distributed under the repository MIT license. They synthesize sfnt tables without loading a system font. The no-break corpus maps printable ASCII, U+00A0, U+2007, U+202F and U+FEFF to a constant-width empty-outline glyph. It tests measurement, embedding and ToUnicode source preservation, not visual glyph design or shaping quality. The synthetic font is not a production font.

Malformed directory fixtures deliberately test offsets, duplicates, nonempty overlaps, directory aliases and empty tables. The allocation regression uses the original 1 MiB / 32-descriptor input with JIT/static warmup outside the measured section; allocation must remain below two input copies plus 256 KiB metadata/exception allowance. The maximum-directory malformed fixture uses only 8 KiB. cmap-candidate aliasing has a separate allocation regression.

sample-progressive.jpg is generated by Pillow from the original Kypelon.Pdf sample-rgb.png artwork. scripts/create-image-fixtures.py reproduces both baseline and progressive JPEG fixtures; both are covered by byte-exact passthrough assertions. No downloaded artwork or third-party font binary was added.

The pre-existing installed-font Thai integration test still explicitly uses KYPELON_TEST_FONT or Windows Tahoma. New hardening regressions never depend on it. Its contextual GPOS test remains intentionally skipped pending the v0.2 text workstream.

## v0.2 source-cluster fixtures

TextPipelineTests uses the same original MIT-licensed synthetic font builder with sorted ASCII, Thai, combining-acute, no-break and emoji cmap entries. Its empty outlines test source/encoding semantics, not visual typography. No system font file is needed for these new regressions. The tests generate per-target extraction PDFs; scripts/validate-text-pipeline.py reads them independently with pypdf/PyMuPDF. Real business-template rendering still uses the explicitly configured installed font.
