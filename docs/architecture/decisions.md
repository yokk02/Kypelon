# Architectural decisions

1. **Original PDF 1.7 engine.** Serialization is implemented from ISO 32000-1 syntax. No generation is delegated to a PDF library, browser or external process. Python readers/renderers are development validators only.
2. **Classic xref first.** Generation-zero objects have explicit reservations and forward references. A counting writer records actual emitted bytes and does not seek. One write per reservation is enforced; exact reference ownership is checked recursively in arrays/dictionaries/stream dictionaries and at write/trailer boundaries. Forward references must already be reserved by the same writer. All reservations must be filled before finalization. A future cross-reference strategy can emit xref streams/object streams without changing layout.
3. **Strict dependency direction.** Kypelon.Pdf fluent builders depend on Layout, Text, Graphics and Core. Layout depends on Text/Graphics; Text and Graphics depend on Core. Core has no dependency on any upper layer or third-party package. AspNetCore depends on Kypelon.Pdf and the ASP.NET shared framework. Six NuGet packages preserve these assembly boundaries.
4. **Separate measure, arrange, render.** Elements measure into local MeasuredBlock trees. Arrange translates typed TextCommand/RectangleCommand/ImageCommand/LinkCommand instructions. Paginator places those instructions in PagePlans. Kypelon.Pdf's render session converts them into PdfCanvas operators and PDF objects. Layout code contains no raw PDF operators.
5. **Top-left logical coordinates.** Graphics opens each page with a Y inversion. Text and images invert their local Y again to remain upright. Fonts retain native font-unit advances and upward-positive offsets until rendering.
6. **Two-pass planning.** Headers/footers reserve measured regions; paragraphs split at line boundaries and tables at row boundaries. The total count is known before page-number templates are resolved. Plans store text and geometry, not serialized/compressed pages. Atomic elements that cannot fit raise contextual errors; no silent vertical overflow.
7. **Forward-only output.** A session emits one page content stream and page dictionary at a time; resources can be written later through reserved references. Compression buffers only the current stream. Xref offsets and lightweight plans scale with document size. Font programs and image pixels remain resident. ToArray explicitly opts into whole-document buffering. Async output calls WriteAsync/FlushAsync directly; no Task.Run or sync-over-async bridges.
8. **Immutable font faces, local encoders.** FontFace owns one immutable font-program buffer and bounded parsed data. Table directory descriptors and selected cmap spans refer into that buffer without per-table/candidate copies. Nonempty ranges cannot overlap each other or the directory; empty glyf/optional tables are legal when required metadata permits them. cmap 4/12 maps Unicode scalars to glyph IDs, hmtx measures advances, head/hhea/maxp/name/OS2/loca/glyf provide required metadata and outline bounds. Per-session FontResource derives Unicode mappings from immutable prepared source ranges and maps (glyph, mapping) to unique CIDs, so aliases are not lost. Complex runs add ActualText; see the v0.2 text ADR. It writes Type0/CIDFontType2 with an explicit CIDToGIDMap and UTF-16BE ToUnicode CMap. Full embedding avoids premature subset corruption. Subsetting belongs between FontFace and resource serialization, with glyph closure/checksum rebuilding tests.
9. **Honest shaping boundary.** BasicTextShaper only maps scalars and native advances. ITextShaper permits glyph positioning without introducing native dependencies into Core. No claim of correct Thai GSUB/GPOS or bidi is made. v0.2 adds validated source clusters, complete-candidate width fitting and immutable prepared runs, with ActualText for complex extraction. The renderer never calls a shaper. See [the text pipeline ADR](text-pipeline-v0.2.md); advanced shaping remains future work.
10. **Determinism scope.** Sorted dictionaries, stable traversal, no random IDs and optional omitted dates give repeatable bytes on a fixed runtime. Flate output can differ between .NET versions. Explicit metadata dates override omitted-date behavior.
11. **Bounded inputs.** Fonts and images: at most 32 MiB per file. Fonts: at most 256 tables, supported cmap formats only, 100,000 format-12 groups, 8,192 format-4 segments, offsets/glyph references checked. Images: 16 million pixels, 32,768 pixels per dimension, CRC and decompressed-length checks. Text elements: one million UTF-16 units; PDF containers: 64 nesting levels; documents: 10,000 pages. These guardrails do not replace a fuzzing/security audit.
12. **Declared project identity.** Kypelon is by Konkaew; package Authors is Konkaew and Product is Kypelon. The MIT license retains the original pre-public contributor attribution alongside the current identity. RepositoryUrl is configurable at pack time. Installed fonts are not redistributed. The repository has no secrets, service credentials or publishing automation.

13. **Typed template recreation.** The user-supplied AEFS HTML is a design reference. A custom Element measures a fixed notification card and emits existing render commands plus URI link hit areas. FlowBuilder.Add permits custom elements without exposing PDF syntax. Rounded rectangles use cubic Bezier paths in Graphics. LinkCommand remains layout geometry; Core owns the Link/URI dictionary and the writer attaches it to the page. International URI paths are escaped and IDN hosts converted to ASCII. Links are validated during Plan before output starts. These dictionaries follow [ISO 32000-1 sections 12.5.6.5 and 12.6.4.7](https://opensource.adobe.com/dc-acrobat-sdk-docs/pdfstandards/PDF32000_2008.pdf). No general HTML renderer is implied.

14. **Cell styles and report templates.** TableCellStyle overrides full text style and/or background at a row/column address (row -1 for headers). MeasureRow and auto-column sizing resolve the same style. Pagination retains source row indices, so styled cells and repeated headers remain consistent across pages. The eDocket sample uses four page templates and small typed graphics elements; its synthetic workflow fixtures stay in the sample project, outside the SDK.

15. **Hardening patch failure semantics (alpha.2).** PdfFileWriter is Active, Finished, Faulted or Disposed. Validate targets, nested references, cycles/depth and syntax before emitting an object prefix. Pre-emission validation/pre-cancellation errors permit retry without consuming reservations. Once a destination write or flush is attempted, any failure/cancellation is terminal because a forward-only stream cannot reliably report or roll back partial writes. Reserve/Write/Finish all reject a faulted writer. Dispose still closes an owned stream, suppressing a secondary disposal error only after an output fault so it cannot mask the primary failure. SaveAsync checks an already-cancelled token before opening FileMode.Create; this does not introduce atomic save semantics.

16. **One source-text normalization policy (alpha.2).** TextNormalization is internal to Text. Public measurement and wrapping normalize CRLF/CR to LF and tabs to four spaces. Measurement returns the widest logical line; Auto table measurement uses it directly. Tokens joined by U+00A0/U+202F/U+FEFF/U+2007 remain indivisible even under emergency wrapping and fail when wider than a full line. Ordinary long words retain grapheme emergency breaks. This limited policy is not UAX #14 or a solution to contextual shaping (F5 was subsequently addressed by v0.2 complete-candidate shaping).

17. **JPEG structural passthrough (alpha.2).** The parser walks bounded marker segments and scan headers, validates supported frame parameters, selectors, spectral/approximation ranges, nonempty entropy segments and terminal EOI, while retaining original bytes. The scan-header rules follow [ITU-T T.81, B.2](https://www.w3.org/Graphics/JPEG/itu-t81.pdf). It does not decode coefficients or certify Huffman tables, restart sequences or progressive completeness. Development readers still validate rendered output independently.

## Extension points

- Kypelon.Pdf.Reader: parse objects/references into a separate read model; do not retrofit parsing into the forward writer. Preserve object identities and original byte ranges for incremental updates.
- Kypelon.Pdf.Edit: page import and resource remapping above Reader, with merge/split/stamp operations reusing Core and Graphics.
- Kypelon.Pdf.Forms and annotations: typed dictionaries/resources in Core with fluent field/annotation models above layout.
- Kypelon.Pdf.Security: encryption filters/object-key derivation at serialization boundaries; explicit permission model.
- Kypelon.Pdf.Signatures: incremental revision and seekable/spooled byte-range signing, separate from forward-only generation guarantees.
- Kypelon.Pdf.PdfA: validation/conformance profiles, metadata, output intents and font policies.
- Kypelon.Pdf.Accessibility: semantic structure tree, language, reading order, marked content and artifact handling planned before PDF/UA claims.
- Kypelon.Pdf.Html/Svg/Charts: adapters producing document nodes or graphics commands. They must not delegate PDF serialization to external engines.

No empty roadmap projects were created. The consolidated xUnit project groups tests by subsystem to keep this first release practical.

18. **Pre-public brand migration.** NovaPdf 0.2.0-alpha.1 became Kypelon.Pdf 0.2.0-alpha.1 before public release. Namespaces, project/package identities and product labels change together; technical APIs and algorithms remain the same. No shims or compatibility packages. Prior evidence retains its original identity; current commands and results are in [migration verification](../development/kypelon-brand-migration.md). The next engineering release remains 0.2.0-alpha.2.
